What is modern .NET?

  • Platform and runtime: .NET 10 provides the runtime, libraries and SDK for building applications.
  • ASP.NET Core 10: Web framework for APIs, MVC, Razor Pages and more.
  • Separate from .NET Framework: Not an in-place upgrade of the System.Web stack.
  • Cross-platform: Windows, Linux and macOS, subject to application dependencies.
  • Development tools: dotnet CLI, NuGet and flexible deployment.

Key features of modern .NET

  • Performance and scalability: High-throughput runtime and web stack; measure real workloads.

  • Modularity: NuGet dependencies and the ASP.NET Core shared framework.

Dependency injection: why it matters

  • Problem: Classes create their own dependencies → tight coupling.
  • Principle: Dependencies are supplied from outside (constructor injection).
  • Benefit: Easier testing and replacement of implementations.
  • ASP.NET Core: Built-in DI container creates registered services.

Constructor injection in ASP.NET Core

Register an abstraction and its implementation
builder.Services.AddScoped<INotificationSender, EmailSender>();
Declare the dependency in the constructor
public OrderService(INotificationSender sender)
  • ASP.NET Core resolves registered dependencies when creating services
  • Prefer constructor injection over resolving services throughout the code

DI service lifetimes

  • Transient — a new instance each time a service is resolved
  • Scoped — one instance per scope (typically one HTTP request)
  • Singleton — one instance for the application service provider
  • Captive dependency — a singleton must not capture a scoped service

Configuration in ASP.NET Core

  • Configuration comes from multiple providers, not just JSON files.
  • Common sources: appsettings.json, environment variables, CLI arguments.
  • Use IConfiguration to read hierarchical keys.
  • Later providers can override earlier values for the same key.

Middleware: the HTTP request pipeline

  • Middleware processes HTTP requests and responses.
  • Components run in registration order on the way in.
  • After next(), execution unwinds in reverse order.
  • Middleware can continue or short-circuit the pipeline.
Beograd, Oktobar 2026
18

Custom middleware: before and after

app.Use(async (context, next) =>
{
    app.Logger.LogInformation("Before");
    await next(context);
    app.Logger.LogInformation("After");
});
  • The position of app.Use(...) changes pipeline behavior.
  • A terminal handler can stop later middleware from running.
Beograd, Oktobar 2026

Middleware as a class

Register in Program.cs: app.UsePassThrough();
Pass-through middleware
public sealed class PassThroughMiddleware(RequestDelegate next)
{
    public Task InvokeAsync(HttpContext context) => next(context);
}
Registration extension
public static class PipelineExtensions
{
    public static IApplicationBuilder UsePassThrough(
        this IApplicationBuilder app)
        => app.UseMiddleware<PassThroughMiddleware>();
}

Built-in middleware and ordering

  1. Exception handlingHandle unexpected errors early in the pipeline.
  2. HTTPS redirection / Static filesRedirect requests / serve files when configured.
  3. RoutingMatch requests to endpoints.
  4. Authentication → AuthorizationIdentify the caller before enforcing access rules.
  5. Endpoint executionRun the selected Minimal API endpoint.
RuleOrder matters; use only the components your app needs.
